## Domain Model

### `ClassVuelo.cs` — flight
`[Serializable]` class with `origen` (origin), `destino` (destination), `costo` (cost), `tiempo` (time), `ruta` (route code) and `lp` (the flight's `ListaPasajeros`).

- The constructor builds the route code as `"SK1" + origin + destination`.
- `ToString()` is overridden with a fixed-width, space-padded row, so the object can be added directly to a `ListBox`. A comment in the code explains this.
- `eliminaPasajero(string a)`: removes the passenger with the given seat number.

### `ClassPasajero.cs` — passenger
`[Serializable]` class with `nombres` (first names), `apellidos` (last names), `edad` (age), `asiento` (seat) and `vueloDelPasajero` (the passenger's flight). `ToString()` builds a padded row for the passenger list.

### `ListaVuelos.cs` — flight list
`ListaVuelos : List<ClassVuelo>`, `[Serializable]`.

- `busquedaCoincidencias(dato, opc)`: search. `1` = route **prefix**, `2` = exact origin, `3` = exact destination.
- `quicksortCosto`, `quicksortTiempo`, `quicksortOrigen`, `quicksortDestino`: recursive in-place quicksort with a middle pivot (Hoare-style partition). Origin and destination are compared by the ASCII code of their first character (`Asc`).

### `ListaPasajeros.cs` — passenger list
`ListaPasajeros : List<ClassPasajero>`, `[Serializable]`.

- `busquedaCoincidenciasNomApel(dato, opc)`: character-by-character **prefix** search. `1` = first name, `2` = last name, `3` = seat, `4` = age.
- `quicksortNombre` (first letter of the name), `quicksortRuta` (4th character of the route code, i.e. the origin letter), `quicksortAsiento` (seat number).

## Graph

### `Grafo.cs` — graph and its node types
Contains four `[Serializable]` classes:

| Class | Role |
|---|---|
| `Grafo` (graph) | Holds `listaNodos`. The constructor `Grafo(ListaVuelos)` creates one node per distinct city, then one adjacency per flight with cost and time weights. Also: `getListaNodos`, `setListaNodos` (adds a node), `eliminarNodo`, `imprime` (console dump), `Clone` (`MemberwiseClone`, shallow). Implements `ICloneable`. |
| `Nodo` (node) | A city plus its adjacency list and its `ElementoDijkstra`. Also has `Primkruskal`/`setPrimKruskal`, a string that accumulates child city names; the Dijkstra classes write to it (`conexiones()`), but nothing reads it. |
| `Ady` (adjacency) | Outgoing edge: target node, `ponderacionCosto` (cost weight), `ponderacionTiempo` (time weight). |
| `Ciudad` (city) | Name (a single letter in practice) and `x`, `y` pixel coordinates on the map. |

### `Arista.cs` — edge
Explicit edge (`origen`, `destino`, cost, time) used to build candidate lists for Kruskal and Prim. Getter names contain the original typos `getNodoDestinon` and `getPonderacionTimepo`.

### `ListaAristas.cs` — edge list
`ListaAristas : List<Arista>`.

- `quicksortCosto`, `quicksortTiempo`: sort candidate edges.
- `seleccionFactibel(candidatos, S)`: Prim helper. Returns the first edge (in sorted order) with exactly one endpoint in the visited set `S`. If none exists, returns a placeholder edge between dummy nodes `"Inicio Vacio ERROR"` / `"Destino Vacio EEROR"`.

## Shortest Paths

### `ElementoDijkstra.cs`
Per-node Dijkstra state: `peso` (tentative distance), `n` (node), `proveniente` (predecessor), `definitivo` (settled). `serReiniciado()` resets it.

### `DijkstraCosto.cs` / `DijkstraTiempo.cs`
Two nearly identical classes. The only difference is whether the edge's cost or time weight is used. The constructor runs the whole algorithm:

1. `Inicio(char)`: finds the start node by comparing the city name to the given character.
2. `iniVecDij()`: resets every node's `ElementoDijkstra`, builds the vector `vD`, and computes an "infinity" value as the **sum of all edge weights**; the start gets 0 and every other node gets "infinity".
3. `generarDijkstra()`: repeatedly selects the unsettled element with the smallest weight (`seleccionaVD`, linear scan), settles it, relaxes its outgoing edges (`actualizarPesos`), and stops when no unsettled element has a finite weight (`checarBandera`).
4. `resFinal()`: for each reachable node, builds a string `total<-node<-predecessor<-…<-start`.
5. `conexiones()` (if `conex` is true): writes each node name into its predecessor's `Primkruskal` string.

`getvD()` returns the result strings.

These two files are the ones changed by commit `ac7a049` in 2026 (dictionary lookups instead of `IndexOf`). See [project-context.md](project-context.md#about-the-2026-change-to-the-dijkstra-files).

### `EDijkstra.cs`
A small class with cost, time, destination, predecessor and settled fields and only a constructor. It is not used anywhere, probably an earlier design of `ElementoDijkstra` (inferred).

## Windows Forms

Each form has three files: `X.cs` (logic, hand-written), `X.Designer.cs` (layout, generated by the Visual Studio designer) and `X.resx` (resources such as embedded images).

### `FormMainVuelos` — main window ("Vuelos Al Qaeda Flying")
- Constructor receives the shared `ListaVuelos` and `Grafo` and fills the flight `ListBox`.
- **Search** (radio buttons Ruta / Origen / Destino + text box): runs on `TextChanged` through `ListaVuelos.busquedaCoincidencias`.
- **Sort** (radio buttons Costo / Tiempo / Origen / Destino): `OrdenarCosto`, `OrdenarTimepo`, `OrdenarOrigen`, `OrdenarDestino`. Each sorts either the full list or the last filtered list, depending on whether the list box currently shows all flights.
- **Add flight** (`buttonAgregarV_Click`): enabled only when every field is filled and the password is `123`. Origin/destination must be a single letter (`A`–`Z`, `Ñ`) and different from each other; cost and time accept digits only; the route field is auto-filled as `SK1`+origin+destination and duplicates are rejected. A city not yet in the graph opens `FormGrafo` in coordinate-picking mode.
- **Delete flight** (`buttonEliminarVuelo_Click`): requires the password; removes the adjacency and orphaned nodes, then the flight. Contains a commented-out block for an adjacency check, with a note the author left for re-enabling it.
- Buttons open `FormGraficoDelAvion` (selected flight), `FormPasajeros` and `FormGrafo` (map, mode 0).

### `FormGraficoDelAvion` — seat map
- Background is the 30-seat cabin plan; each seat is a button `buttonAsiento1…30`.
- `InicializaAsiento()`: paints occupied seats maroon and disables them.
- All seat buttons share the `buttonAsiento1_Click` handler, which stores the seat number (`Int32.Parse(boton.Text)`) and enables "Reservar Asiento".
- "Reservar Asiento" opens `FormRegistoPasajero`; if the reservation succeeds, the seat map closes.
- Contains many empty event handlers left over from the designer.

### `FormRegistoPasajero` — passenger registration
- Shows the flight data (route, origin, destination, cost in "Pesos", time in "Min", seat) in disabled, non-editable text boxes.
- Name fields accept letters and spaces only (converted to uppercase); age accepts digits only.
- "Reservar" creates a `ClassPasajero`, adds it to the flight's passenger list and shows a confirmation. "Cambiar Asiento" goes back to the seat map.

### `FormPasajeros` — passenger list
- Collects every passenger from every flight into one `ListaPasajeros`.
- **Filter** by first name, last name, seat or age (prefix search, input validated by type).
- **Sort** by name, route or seat (`OrdenamientoNombre`, `OrdenamientoRuta`, `OrdenamientoAsiento`); shows "No hay elmentos para ordenar" when the list is empty.
- **Delete passenger**: removes them from their flight and from the combined list.

### `FormGrafo` — map and algorithms
- Constructor `FormGrafo(Grafo g, int bandera, ListaVuelos lv)`. `bandera` (flag) selects the mode:
  - `0`: normal map with analysis tools;
  - `1` / `2`: "AGREGA CIUDAD ORIGEN" / "AGREGA CIUDAD DESTINO". A click on the map stores the point (`getX()`, `getY()`) and closes the window.
- `DibujarNodos` / `DibujarAdyacencias`: GDI+ drawing of pins, arrows and labels (mode 1) or thick red spanning-tree edges (mode 2).
- `buttonBorrarCiudad_Click`: after confirmation, deletes a city with all its flights and adjacencies.
- `buttonCostosKruskal_Click`: **Kruskal** by cost (see [algorithms.md](algorithms.md#kruskal-by-cost)).
- `buttonTiemposPrim_Click`: **Prim** by time from the selected city (see [algorithms.md](algorithms.md#prim-by-time)).
- `button1_Click` ("Ruta Optima (Dijkstra)"): runs `DijkstraCosto` or `DijkstraTiempo` from the selected city, depending on the radio button.

## Class-Designer Stub Properties

Several classes contain properties like:

```csharp
internal ListaAristas ListaAristas
{
    get => default(ListaAristas);
    set
    {
    }
}
```

(e.g. `Arista.ListaAristas`, `ClassVuelo.ListaVuelos`, `ClassPasajero.ListaPasajeros`, `Grafo.Nodo`, `Nodo.Ciudad`, `Nodo.Ady`, `FormMainVuelos.FormGrafo`, …). They do nothing at runtime. Visual Studio's **Class Designer** inserts this code when an association is drawn in `ClassDiagram1.cd`, and the property names match the associations shown in the diagram. They are part of the original code and were left as they are.
